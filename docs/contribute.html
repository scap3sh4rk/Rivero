Build and contribute

Everything you need to run, test, release and improve Rivero.

Build it

You need the Flutter SDK matching .github/workflows (currently 3.50.0), Android Studio or the Android SDK, and Java 21 for release builds.

git clone https://github.com/scap3sh4rk/Rivero.git
cd Rivero
flutter pub get
dart run build_runner build --delete-conflicting-outputs   # Drift generated code
./tool/verify.sh                                           # format, analyze, test
flutter run                                                # debug on a device

Generated *.g.dart files are not committed. After running build_runner, run dart format ..

The quality gate

./tool/verify.sh must pass before every commit. It runs:

  1. Format checkdart format --output=none --set-exit-if-changed .
  2. Static analysisflutter analyze with very_good_analysis rules
  3. Testsflutter test, over 280 tests

Principles to keep

  • Integer minor units only. Money is int paise. No floating point in persistence or calculation.
  • Two-tier ledger. Physical accounts and plan categories stay decoupled; plans never create or duplicate money.
  • Zero READ_SMS. Capture uses notification access only.
  • Conservation. unallocated = salary − Σ allocated; allocations never exceed the salary.
  • One writer. Balance and budget changes go through LedgerService, atomically.
  • Local-first and encrypted. No plaintext database, no data leaves the phone unless the user starts a backup.

Branches and commits

BranchUse
developAll active work: features, fixes, tests, migrations
mainRelease branch. A push to it builds and publishes a release

Keep commits focused with a clear message ("fix(plan): …", "feat(capture): …"). Add or update a test with every behaviour change; money paths need a regression test.

Releases

.github/workflows/release.yml runs on every push to main: it verifies, builds a signed APK and App Bundle with Java 21, and publishes a GitHub Release tagged v<version>-<run> with notes from .github/release-notes.md plus generated change notes.

Signing uses repository secrets: ANDROID_KEYSTORE_BASE64, ANDROID_KEYSTORE_PASSWORD, ANDROID_KEY_ALIAS, ANDROID_KEY_PASSWORD. Without them the build falls back to the debug key and is not fit for distribution. CI (ci.yml) runs the quality gate on every push and pull request. This site is published by pages.yml when files under docs/ change on main.

Google Drive backup setup

Backup needs a Google Cloud project with the Drive API enabled and OAuth clients: a Web client (its ID is set in lib/core/backup/drive_backup.dart) and an Android client for each signing key (package dev.scap3sh4rk.rivero with that key's SHA-1). iOS needs its own iOS client.

Known limits and roadmap

AreaStatus
iOSProject configured; not yet built or tested on a device. No passive notification capture on iOS, so it relies on manual logging, bill scan and statement import.
Google Drive sign-inNeeds a Drive OAuth client per signing key; verify on a release build.
Statement importCSV only, experimental; history only, balances unchanged.
APK sizeAbout 98 MB (bundled fonts and ML Kit text recognition); the App Bundle is smaller per device.
Spends from the salary accountWhen the salary account is separate from the spending account, spends from it do not reduce Safe to spend (by design).
NextiOS device testing and more bank message formats.

Contributing

Use the issue templates: Bug report, Feature request, Bank message not recognised and Question. Issues and pull requests are welcome at github.com/scap3sh4rk/Rivero. The most valuable contributions right now: real-world bank message formats (with personal details removed) for the parser tests, iOS testing, and accessibility feedback.
