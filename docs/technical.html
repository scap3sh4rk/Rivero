Dependencies point inward: features → providers → core. Core services take a database and have no Flutter UI imports, which keeps nearly all behaviour unit-testable against an in-memory database.

Transaction type and state

Types: expense, income, creditCardPurchase, creditCardSettlement, atmWithdrawal, cashExpenditure, internalTransfer, bucketFunding, investmentContribution, investmentRedemption, walletTopup, balanceAdjustment, refund, reversal, reimbursement, lending, borrowing, repayment, planTransfer.

States: needsReview (no effect yet) → confirmed (applied) → reconciled (matched with a partner or bank message); or ignored. Balances and budgets change exactly once, when an entry becomes applied.

Migrations

Versions 2–11 add columns and tables, repair data (v8 resets inflated carry-over, v9 clears obsolete bucket links), add indexes on transaction time, account, state and amount (v10), and add card billing days (statement_day, payment_due_day) and a debt due_date (v11). Restoring an older backup applies the same repairs.

The ledger

LedgerService is the single writer of balance and budget effects. Every path (capture, confirm, manual entry, plan, import) goes through it.

  • Atomic: record, confirm, remove, set-balance and transfer conversion each run in one database transaction.
  • Race-safe: balance and spent updates are single SQL UPDATE … SET x = x + ? statements; confirm flips the state with a conditional update and only the caller that flipped it applies the effects, so a double tap applies once.
  • Budget rules: cash outflows consume the spending bucket; card purchases do not (the bill is reserved instead); refunds give budget back; plan-category payments mark the category paid.
  • Undo: removing an applied entry reverses balance, budget and category-paid effects; history-only imports reverse nothing; deleting a bill removes its unpaid dues.
  • Recording a debit that matches a live autopay rolls that autopay to its next date.

Parser notes

  • Handles formats such as Rs 450.00 debited, INR 1,299.00, ₹500 and SBI-style debited by 500.0 with no currency symbol.
  • Confidence = amount (0.35) + direction (0.20) + account mask (0.15) + reference (0.15) + merchant (0.10) + known sender (0.05). At 0.85 and above, and with a certain account, it auto-confirms.
  • OTPs are never stored (the log holds a placeholder).
  • The notification title is used as the sender header for SMS apps (VM-SBIUPI), validated against known TRAI/DLT entity codes.

Reconciliation

Self-transfer matcher pairs a debit and a credit on different accounts only if the kinds can be transfers, amounts equal, and either both references match or neither exists and the legs are within two minutes. Refund matcher links refunds to their original purchase by merchant and amount. Paired legs become internalTransfer and leave spending.

Plan engine

  • SalaryPlanService.apply validates the split (Σ ≤ salary), writes buckets, handles same-cycle revision vs new cycle (carry-over), and delegates money moves.
  • PlanTransferService computes moves (movesFor: tracked destinations only), plan-only categories (planOnly), syncs deterministic entries (sync), guards against shortfalls and can re-key a cycle when the pay day changes.
  • Mid-month setup is handled by alreadyMoved: no transfers, categories marked paid, remembered per cycle.
  • WaterfallAllocator allocates by priority with integer percent maths; the conservation invariant unallocated = salary − Σ allocated is tested.

Autopay engine

  • upcomingMandates returns active mandates from 5 days overdue to the cycle end; reserveUntil multiplies by the number of weekly debits left.
  • MandateTracker.onDebit matches by whole-word payee and amount (or exact amount alone when only one fits); rollOverdue runs on start/resume and moves stale dates forward; addMonths clamps month ends.

First run, tour and intro

  • There is no setup wizard. ensureDefaults creates the single everyday-spending category; accounts, salary and other categories are added in place. The first plan links an unlinked spending category to the salary account so Safe to spend follows a real balance.
  • AppTour: a dialog card over the live app that switches tabs behind it (selectedNavIndexProvider); shown once (tour_done), replayable from Settings. GetStartedCard on Home ticks off "add accounts" and "set a plan".
  • Home's header shows the logo and BrandWordmark, "Rivero" revealed left to right with a blue light sweep once per launch.
  • RiveroFab is the single "add" button (bottom right, same size and colour) used by every page that adds something; RiveroAppBar carries the eye (hide amounts) on every page.

Card cycles and money owed

  • CardCycle.of(statementDay, paymentDueDay, now) gives the last and next statement dates (month ends clamped), days left in the cycle, the next due date and days to it; CardAffordability compares what a card owes with the bank and cash balances.
  • DuesService handles three kinds: split and lent (owed to you) and borrowed (you owe). borrow records an inflow typed borrowing; repay an outflow typed repayment. Neither is income or spending. youOweDueBy(cycleEnd) feeds Safe to spend (dated debts due before payday).
  • Bills & commitments (Owed tab) composes cards (cycle, limit, available, can-pay), loan accounts and autopays due before payday from the same providers as Safe to spend.

Providers and refresh

Streams from Drift DAOs feed Riverpod providers. stsBreakdownProvider composes buckets, accounts, mandates, dues, the pay cycle and settings into one StsBreakdown; liveSafeToSpendResultProvider derives from it. todayProvider is refreshed at midnight and on resume; currentPaycycleProvider recomputes from it and from the last planned cycle (early salary).

Platform layer (Android)

  • RiveroNotificationListener: filters sources and money-like text, writes to CaptureQueue, nudges the live app.
  • Diagnostics: counters only (heard, queued, no money, hidden text, last package and time; never message text) shown in Settings → Capture → Recent captures.
  • The user's primary UPI app is stored natively (setPrimaryApp; the picker lists only installed apps that can open upi://pay, via upiApps) so the listener reads its notifications even when it is not in the built-in allow-list; in Dart it becomes an extra trusted package for the parser, which also reads the amount from the notification title when the body has none.
  • CaptureQueue: AES-256-GCM with a non-exportable Keystore key; migrates an older plain queue; cleared by "Delete all data".
  • MainActivity (FlutterFragmentActivity for biometrics): channel methods isEnabled, openSettings, drain, clearQueue, setSecure, postTest.
  • Manifest: no READ_SMS; allowBackup="false" so the database can never be copied without its key.

Backup format

{ format: "rivero-backup", v: 1, kdf: "pbkdf2-sha256", iter: 210000,
  salt, nonce, mac, data: base64(AES-256-GCM(json)) }

json = { schema, createdAt, physicalAccounts, allocationBuckets, transactions,
         mandates, associatedTitles, dues, appSettings, media[] }

Restore: authenticate and decrypt, refuse a newer schema, write pictures back and re-point their paths, wipe and insert parents before children inside one transaction, fill columns added since, then apply the v8/v9 repairs for older backups.

Design system

"Ink & Sky": a pure-black dark theme with a single blue accent, and a warm paper light theme. Colour carries meaning (categories, accounts, money in and out), not decoration. Tokens live in rivero_tokens.dart; this documentation site uses the same values. Six bundled fonts (Urbanist default, Inter, Plus Jakarta Sans, Manrope, DM Sans, JetBrains Mono for figures).
